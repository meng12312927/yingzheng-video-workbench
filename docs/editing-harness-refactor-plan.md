# 映证 Editing Harness 改造执行计划

> 状态：已批准并执行；核心 Harness 已落地，质量与专业适配继续迭代  
> 分支：`codex/editing-harness-refactor`  
> 初始基线：66 个自动化测试通过；当前回归：80 个自动化测试与 Ruff 通过

当前实现快照：阶段 A、B、D、F、G 的核心闭环已完成；默认交互已收敛为两次确认。需求骨架不再在看素材前让模型补常识，素材访谈使用代码检索加一次 LLM 提问；候选使用代码混合检索加一次 LLM 批量排序，并以可验证候选补齐时长。相同素材转录和 Embedding 索引可复用，候选预览按点击生成。手机审核、PostgreSQL/Redis、Docker Compose、健康检查和版本化组织配置已经实现。词级边界、说话人识别、低码率审核代理、前端版本对比、单项要求重算入口和更多专业编辑器 Adapter 继续直接实施。

## 1. 改造目标

映证从“本地活动视频粗剪工具”演进为可审核、可追溯、可接入不同剪辑软件的 AI 剪辑决策 Harness。映证负责素材理解、有限访谈、证据检索、剪辑规划、人工 Gate、版本和审计；FFmpeg、剪映、Premiere、Resolve 等负责预览、执行或专业精修。

产品主流程调整为：

```text
上传一段或多段原素材
→ 每段素材独立预检、转录、摘要与索引
→ 聚合生成素材大纲
→ AI 基于检索证据集中提出少量问题
→ 在同一页确认问题答案与剪辑任务书
→ 证据化候选、完整表达校验与时长规划
→ 审核通用剪辑时间线
→ FFmpeg 预览 / 剪映交接包 / OTIO 等编辑器交付
→ 导出检查、审计与局部重算
```

## 2. 不可变设计约束

1. 用户可以上传一段或多段素材，两种情况复用同一领域流程。
2. 每段素材独立分析，不在分析、转录或检索前拼成长视频。
3. 每条转录、证据、候选都绑定 `source_asset_id + source-local time`。
4. 只有生成预览或成片时，才按已批准时间线组合选中片段。
5. 单段素材失败不阻断其他素材；支持单素材排除、重试和重新分析。
6. 不默认把全部转录反复发送给 LLM；使用素材大纲、受限检索和 Token 预算组装上下文。
7. AI 先给出时间点和推荐答案，用户只处理业务歧义，不要求用户手写时间码。
8. 通用时间线是事实来源，编辑器专属字段不得进入核心领域模型。
9. FFmpeg 保留为预览与基础交付后端，不再代表产品唯一执行方式。
10. 剪映首版使用稳定交接包；私有草稿或 UI 自动化只能是关闭默认值的实验适配器。
11. 所有模型建议必须经过版本、证据、素材边界和人工 Gate 约束。
12. 旧任务允许兼容读取，不做破坏性迁移。

## 3. 决策规则调整

真实用户验证继续记录需求确认耗时、`must` 召回、审核时间、人工补片和返工，但不再作为 V1.1 工程能力的启动门槛。以下能力直接进入实施路线：

- 完整表达边界和问答上下文保护。
- 确定性时长规划器。
- 候选多样性、完整度和重复度控制。
- 活动流程表、主持稿、名单、产品资料等辅助证据。
- 人名、职务、奖项、产品名和合作单位确认。
- 失败恢复、局部重算、跨进程恢复和可观测性。
- 手机轻量审核、Token 过期/撤销和幂等提交。
- PostgreSQL/Redis 可替换存储边界、Docker Compose 和健康检查。
- 组织品牌、术语和发布限制配置。

真实指标仍用于决定优先级、默认开关和后续删减，不能用来伪造产品收益。

## 4. 分阶段实施

### 阶段 A：冻结基线与文档对齐

- 创建独立改造分支，记录测试基线和回退点。
- 修改 PRD、技术方案、README 和架构图。
- 新增任务产物 `schema_version`，明确旧任务兼容策略。
- 将状态主线改为素材优先：`ingesting → transcribing → material_ready → interviewing → requirement_confirmed → planning → awaiting_review → exporting`。

验收：文档与代码名词一致；当前测试不退化；无破坏性数据迁移。

### 阶段 B：分素材领域模型与时间语义

新增：

- `SourceAsset`：原始文件、哈希、顺序、媒体信息和分析状态。
- `SourceTranscript`：某一素材的转录版本、语言、模型和片段。
- `SourceAnalysisResult`：某一素材的摘要、证据和错误。
- `TaskMaterialSet`：一个任务内全部素材及聚合状态。

改造：

- 每段素材分别预检和 Whisper 转录。
- 删除多素材分析前的 `merged_source.mp4` 依赖。
- `TranscriptSegment`、`Evidence`、`CandidateClip` 增加 `source_asset_id`。
- FFmpeg 预览从多个原素材按计划动态取段。
- 单素材失败保存稳定错误码，其他素材继续。

验收：三段素材分别落盘；候选可精确回到原文件；源时间误差不超过一帧；单段失败可局部重试。

### 阶段 C：素材理解与上下文 Harness

新增 `MaterialProfile`：

- 每段素材摘要、主题、人物/说话人线索、环节和风险。
- 跨素材活动结构大纲和重复内容线索。
- 可预览的代表证据。
- 转录置信度和无语音素材状态。

新增受限工具：

- `get_material_outline`
- `search_transcript`
- `expand_transcript_context`
- `get_source_asset`
- `preview_evidence`

新增 `ContextAssembler`：按阶段组装素材大纲、已确认答案和相关证据；为每次模型调用设置 Token 预算，长素材禁止默认全文输入。

验收：长素材每轮只发送必要上下文；素材大纲可追溯；工具范围、耗时、Token 和降级均记录。

### 阶段 D：证据化剪辑访谈

现已将固定澄清问题演进为素材驱动的 `MaterialInterviewAgent`。每个问题包含：

- 问题、询问原因和不回答的影响。
- AI 推荐答案与可选答案。
- 关联素材、证据和预览片段。
- 采用、修改、忽略和提前结束入口。

提问围绕必须/禁止内容、人物、长讲话保留方式、同类环节取舍、节奏和交付规格。用途、受众、目标时长、风格、字幕和音乐在同一任务书表单直接确认。单次最多 5 题；每题可补充或忽略，最后统一提交，不重复确认。

验收：问题不是固定模板；与素材证据绑定；用户不填写时间码；答案生成版本化任务书并使旧批准失效。

### 阶段 E：完整表达、时长规划与候选质量

#### E1 完整表达边界

- 使用 Whisper 词级时间戳（后端支持时）。
- 识别说话人变化、问答轮次和必要承接关系。
- 检测连接词、因果句、未结束语气和标点闭合。
- 先吸附到完整语义单元，再向允许的镜头/ASR 边界扩展。
- 配置讲话最短上下文和前后缓冲。
- 必要时将问题和回答作为一个不可拆语义组。

目标：不从半句话开始、不在表达中途结束、不只保留缺少上下文的回答、不机械拼接不完整语句。

#### E2 确定性时长规划器

```text
目标总时长
→ must 项预留预算
→ should 项分配剩余预算
→ 限制单人连续讲话
→ 为开场/主体/高潮/总结和过渡预留结构预算
→ 合并去重后重算
→ 优先扩展已有完整片段
→ 仍不足时提出具体补片建议或允许计划级短版例外
```

输出每项要求预算、已用时长、缺口、可扩展候选和建议补充内容。

#### E3 候选质量与多样性

- MMR 或等价多样性去重。
- 内容完整度、信息密度和证据质量评分。
- 同一讲话重复度检查和连续讲话上限。
- 开场、主体、高潮、总结等活动结构覆盖。
- Reranker 与 BM25/RRF 基线同集对照，无稳定收益则关闭。

验收：完整表达、时长误差、重复率、结构覆盖和人工边界修改次数进入评测报告。

### 阶段 F：通用时间线与执行器适配

新增 `CanonicalTimeline`，包含：

- 原素材引用和轨道。
- `source_in/source_out` 与 `timeline_in/timeline_out`。
- 需求、证据、字幕、标题、转场、标记和用户决定。
- 任务书版本、批准版本和导出版本。

拆分：

- `PreviewRenderer`：首个实现为 `FFmpegPreviewRenderer`。
- `EditorAdapter`：`validate/export/inspect_result`。
- `HandoffPackageAdapter`：输出素材、SRT、CSV、JSON、预览和导入说明。
- `OTIOAdapter`：输出可往返读取的 `.otio` 时间线。

剪映交接包首版不依赖私有草稿；Premiere/Resolve 等通过 OTIO/FCP XML/EDL 后续适配，软件专属特效不作跨软件承诺。

验收：同一批准时间线可生成 FFmpeg 预览、剪映交接包和 OTIO；Adapter 失败不污染计划状态。

### 阶段 G：辅助资料与高风险专有名词

支持上传：活动流程表、主持稿、人员/职务/奖项名单、产品和合作单位资料。资料按文件版本、页码/行号或表格位置生成 `event_document` 证据。

新增高风险确认队列：

- 人名、职务、奖项、产品名、组织名和合作单位。
- 转录文本、辅助资料和用户确认值并排显示。
- 字符差异不能由模糊匹配自动通过。
- 用户确认值可进入当前任务和可管理组织词典。

验收：所有高风险文字有来源、确认状态、版本和删除入口；模型置信度不能代替人工确认。

### 阶段 H：失败恢复与局部重算

- 单素材、单需求、单候选批次和单 Adapter 独立重试。
- Embedding 失败显示明确降级状态。
- LLM 超限时自动缩小批次，只重试失败批次。
- 修改某项要求时，仅失效关联候选和下游计划。
- 已完成转录、索引、缩略图和预览不重复生成。
- 长任务从最后成功节点恢复。
- 所有重试保存原因、次数、输入版本和结果。

验收：局部修改不会重跑无关素材；重启后恢复；重复事件不产生重复渲染或导出。

### 阶段 I：审核前端体验

- 显示当前阶段、整体进度和每段素材状态。
- 素材卡片显示摘要、转录风险、缩略图和代表证据。
- 访谈一次展示一题，带 AI 推荐、预览、采用/修改/忽略/结束。
- 候选显示缩略图、波形、关键句高亮和来源文件。
- 时间调整使用可视化双端滑块，数字作为高级选项。
- 显示各要求时长预算、总时长缺口和可扩展片段。
- 风险、缺失项、降级和普通提示分级。
- 支持版本对比和只重新分析某项要求。
- 高级样式折叠，减少页面上下跳转。

验收：不暴露内部 ID/枚举；用户始终知道下一步；桌面与移动窄屏无横向溢出。

### 阶段 J：V1.1 直接工程化

以下能力不等待真实指标门槛，按依赖顺序实施：

1. 手机轻量审核链接、二维码、短期 Token、过期、撤销和幂等提交。
2. 低码率审核代理，原始素材默认留在本地或受控存储。
3. PostgreSQL `TaskRepository/EventRepository` 可替换实现。
4. Redis 仅用于短期会话、幂等键、任务锁和缓存，不作为事实来源。
5. Docker Compose、健康检查、结构化日志和任务资源指标。
6. 组织品牌、专有名词、发布限制和模板配置；所有记忆有来源、作用域、版本和删除入口。

本地 JSON/JSONL 实现继续作为开发和单机模式，不强制所有使用者安装数据库。

### 阶段 K：评测与交付

保留离线与真实评测两层，不混合指标。新增：

- 完整表达通过率、问题/回答上下文保留率。
- 时长预算误差和计划缺口解释率。
- 候选重复率、多样性和活动结构覆盖。
- 专有名词确认与修正次数。
- 局部重算范围、缓存命中和恢复成功率。
- 每阶段 Token、延迟、失败、重试和成本。
- 时间线源引用准确率、Adapter 导出完整率和 OTIO 往返一致性。
- 手机审批 Token 安全、幂等和撤销测试。

最终演示必须覆盖：多素材独立分析 → 素材大纲 → 证据化访谈 → 任务书 → 完整表达候选与时长预算 → 审核 → FFmpeg 预览 → 剪映交接包/OTIO → 审计和局部重算。

## 6. 完成定义

完成不以“添加了某个框架”为判断，而以以下能力同时成立为准：

- 一段或多段素材均独立分析，且可以局部失败和重试。
- AI 问题来自素材证据，用户不需要提供时间码。
- 候选是完整语义单元，时长有确定性预算和缺口解释。
- 每个时间线片段能追溯到原文件、任务书、证据和用户决定。
- 同一批准时间线可以由多个 Adapter 消费。
- 当前 FFmpeg 预览不退化，剪映交接包和 OTIO 可验证导出。
- 高风险专有名词有人工确认流程。
- 修改需求只重算相关部分，任务中断可恢复。
- 电脑审核、手机轻量审核、存储和部署边界均有测试与安全约束。
