# 可复现案例：运动会开幕式为什么被选中

本案例来自仓库内的去标识离线评测夹具 `school-sports-opening`，用于展示映证的证据链，不冒充真实用户研究结果。

## 1. 用户原始要求

> 运动会回顾必须包含开幕式，给师生和家长观看。

系统将其编译为结构化要求：

- 场景：学校活动。
- 受众：师生和家长。
- 优先级：`must`，必须包含开幕式。
- 验收规则：成片中必须出现至少一条开幕证据。

## 2. 可引用素材证据

转录证据包含三个带稳定 ID 的时间窗口：

| 时间 | 证据内容 | 是否相关 |
| --- | --- | --- |
| 00:10–00:16 | 校长宣布本届运动会正式开幕 | 是 |
| 00:40–00:46 | 运动员正在检录准备比赛 | 否 |
| 01:30–01:36 | 观众为运动员加油欢呼 | 否 |

候选 Agent 不能读取整份转录，只能通过 `search_evidence` 检索当前任务书要求允许的证据窗口。

## 3. 候选与确定性校验

系统返回 00:10–00:16，并引用“正式开幕”。随后由代码检查：

1. 证据 ID 存在且属于当前任务。
2. 引文是证据原文中的真实内容。
3. 候选时间范围没有超出证据与源视频边界。
4. 证据关联的是当前 `must` 要求，而非其他需求。

任何一项失败，候选都不能进入自动时间线，只能进入拒绝记录或人工复核。

## 4. 可复现实验结果

运行：

```bash
.venv/bin/python scripts/run_eval.py
```

当前 6 个去标识任务上，BM25、RRF 和 RRF + Rerank 的 Recall@3、MRR、NDCG@3 均为 1.0；原始引用中有 1 条故意构造的错误引用，被确定性校验拒绝，因此校验后的幻觉引用率为 0。

这个结果证明的是“检索和引用校验链路可重复运行”，不证明真实用户一定更省时。真实价值仍需按照[真实用户验证方案](real-user-validation.md)测量。
